# Bulletin - Pilot incident notes

**Owner:** Mobility Programs
**Effective:** 2026-07-23 Pilot incident notes should describe the observed issue, customer impact, owner, and next step. Avoid leaving placeholders such as `follow up later` or `need details`.

## Examples

Use `Docking station 4 failed to confirm return at 3:12 PM; field tech reset station; monitor for repeat event through Friday.` This gives reviewers enough information to decide whether the issue affects launch readiness.

## Review Process

Program managers will check incident-note columns before customer reviews. If a note depends on Engineering confirmation, mark the owner and expected confirmation time.

## Customer Review

Handling Before a dashboard is shown externally, remove placeholder language and verify that each incident has a current owner. If an incident is still awaiting vendor confirmation, say that directly rather than guessing a cause. Pilot dashboards should not include public-policy commentary unless the customer has asked for a policy discussion and Legal has approved the language.
