# Bulletin - Shared drive shortcuts Do not move source folders when creating shortcuts in the shared drive. Use the shortcut option instead of dragging the folder into another team space.

If you accidentally move a folder, contact IT with the original location and approximate time. Shortcuts should show the small arrow icon in the drive view.
If you do not see the arrow, you may have moved the source folder instead of creating a shortcut.

## Recovery Guidance

If a source folder is moved by accident, stop making additional changes and contact IT with the original folder path, new folder path, and approximate move time. IT can usually restore the folder location more quickly if permissions have not been changed afterward.

Do not create duplicate folders to "fix" a missing shortcut. Duplicate source folders can split comments, approvals, and version history across two locations. Use shortcuts for cross-team visibility and leave the original folder under its owning team's space.

## Permission Handling

Creating a shortcut does not grant access to the underlying folder.

If a colleague cannot open a shortcut, ask the folder owner to review permissions instead of forwarding a copied file. IT will treat repeated duplicate-folder incidents as a training issue for the owning team, not as a storage outage, because duplicates can break approval trails and cause teams to revise different versions of the same document.
