# Bulletin - Public Dashboard Language Bulletin ID: AN-26-0506 Audience: analysts and command-staff packet contributors Public dashboards should be described in neutral, methodological language. Avoid wording that implies policy conclusions unless a command reviewer has asked for that framing. Analysts can describe patterns, data limitations, call-code changes, and confidence concerns; elected officials and command staff decide how to present policy choices.

Preferred wording:

| Instead of | Use |
|---|---|
| "crime is surging because patrol is understaffed" | "reported incidents increased in this area while staffing levels varied by shift" |
| "overtime is the only answer" | "overtime is one staffing mechanism reflected in the budget materials" |
| "the public is afraid" | "resident complaints increased in the listed categories" |
| "the map proves" | "the map suggests" or "the map shows reported incidents" |

Analysts should also note code changes that affect comparisons. A clean methods note prevents later correction and keeps staff packets from becoming advocacy documents. The bulletin intentionally separates data-method language from policy advocacy.
An analyst may privately hold views about overtime, staffing, or elected officials, but the packet contribution should stay within methodology, limits, and observed patterns.
Supervisors should keep review comments tied to the packet itself rather than asking why an analyst follows a public budget debate. Distribution:

| Sent to | Purpose |
|---|---|
| Analysis unit | dashboard language standard |
| Records counter lead | public call-log category matching |
| Command packet reviewer | final wording check |
| Dispatch Systems | code-change note confirmation |

The bulletin was drafted before the May Council packet cycle and circulated to the whole analysis unit.
